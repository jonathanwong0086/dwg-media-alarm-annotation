# 介质报警分类规则

三类报警的判定依据、数据来源、边界情况。

## 一、可燃（火灾危险性甲类/乙类）

依据 **GB 50016-2014《建筑设计防火规范》表 3.1.1**：

| 类别 | 判定 | 是否标可燃 |
|------|------|-----------|
| 甲类 | 闪点 < 28°C 的液体；爆炸下限 < 10% 的气体 | ✅ 是 |
| 乙类 | 28°C ≤ 闪点 < 60°C 的液体 | ✅ 是 |
| 丙类 | 闪点 ≥ 60°C 的液体；可燃固体 | ❌ 否 |
| 非可燃 | 不可燃液体/固体/气体 | ❌ 否 |

- 数据来源：**物性表"火灾危险性类别"列**（由 chem-properties-excel 生成）
- 判定函数 `lib.is_combustible_fire_class`：文本含"甲"或"乙"且不含"非" → 可燃
- **不使用硬编码物料清单**。可燃范围随物性表更新而更新。

> 为什么不硬编码：不同项目介质不同，且甲乙丙类由闪点/爆炸下限严格划分，
> 人工列表易漏(如一氧化碳、多聚甲醛也可能是甲乙类)。以物性表为准最可靠。

## 二、有毒

- 依据：**物性表"是否被列入有毒气体检测目录"列**
- 该列汇总了《高毒物品目录》、GB/T 50493、HG/T 20660、剧毒物质等四来源
- 判定：单元格含"是"或"应设" → 有毒
- 数据来源同为 chem-properties-excel 物性表

## 三、氧含量报警

- **默认严格**：介质列文本含 `氮 / N2 / N₂` 才触发
- 离心机(C 前缀)、耙式干燥器(D/DR 前缀)常用**氮气惰性保护**，但设备表介质列
  往往只写工艺介质、不写氮气 → 默认不会触发
- 这类设备若实际需要氧含量报警，由用户用 `--oxygen-tags C1001,DR2001` **显式指定**
- 传入的位号可以是基础位号或完整位号，脚本对两者都匹配

## 四、有毒优先（有毒 vs 可燃互斥）

一台设备**既有毒又可燃**时，**只按有毒处理，不再标注可燃**。

- 有毒气体探测是更高级别的防护要求，标了有毒就不必再叠加可燃标注，避免同一台设备在两个类别块重复出现造成图面冗余。
- 实现：`classify()` 末尾 `if toxic and combustible: combustible=False`（同时从 `hit` 移除可燃命中）。
- 例：介质为"苯"（甲类可燃 + 有毒）→ 只进有毒块。介质为"甲醇"（甲类、非有毒）→ 仍进可燃块。
- 氧含量报警是独立轴，不受此规则影响，可与有毒/可燃并存。

## 介质名归一化匹配

物料 token 与物性表匹配前先**归一化**（`lib.normalize_token`），再做**精确匹配**：

- 剥离浓度前缀 `^\d+(\.\d+)?%`（`40%二甲胺水溶液`→`二甲胺水溶液`）
- 剥离数量前缀 `少量|微量|痕量|大量|适量|约|含|部分`（`少量乙腈`→`乙腈`）
- 剥离尾字 `等`（`甲苯等`→`甲苯`）
- 连接词 `和/及/与` 与顿号等一并作分隔符（`三乙胺和二乙胺`→`三乙胺`+`二乙胺`）

> **只剥修饰词，绝不做子串包含匹配**。子串匹配会把 `三乙胺盐酸盐` 误判成 `三乙胺`、`溴虫腈` 误判成 `溴`——它们是不同物质。归一化后仍走精确相等，本身是独立物料名的就匹配不到、按未命中处理（需要时补进物性表）。

## 位号匹配：为什么用基础位号

设备表与布置图的尾缀经常**双向不一致**：

| 布置图位号 | 设备表位号 | 情况 |
|-----------|-----------|------|
| P1001 | P1001AB | 布置图用系列名，设备表拆开 |
| F2001AB | F2001 | 布置图拆开，设备表用系列名 |
| V3001C | V3001AB | 两边尾缀都不同 |

介质是按**整个设备系列**描述的，所以去掉尾缀(`get_base_tag`)按基础位号匹配最稳健。
`P1001`、`P1001A`、`P1001AB` 都归一到 `P1001`。

## 多报警设备

一台设备的介质可能同时命中多个类别。标注时在命中的每个类别块各出现一次，确保每类报警都被看到。**但**受"有毒优先"约束：同时命中有毒和可燃的设备只进有毒块（见上）。可燃/有毒 与 氧含量报警 之间不互斥，可并存。

## 跨楼层设备：多图框、多处标注

同一设备位号可能在图纸里出现**多次**：

- **跨楼层**：设备贯穿多层，位号在不同图框各画一次 → 在**每个出现的图框**都标注。
- **同层多处**：位号在同一图框出现多次 → 该图框内**每处都画圈+引线**，标签后缀 `（本图框N处）`。

数据结构：`detect_frames.py` 的 `tag_coords` 用坐标列表 `{tag:[[x,y],...]}` 保留全部出现位置，`frames[*].instances` 记录每次出现的 `[tag,x,y]`。标注脚本按 `instances` 逐次绘制。

> 1.0.0 的 bug：`tag_coords` 用单坐标 `{tag:(x,y)}`，同名位号被后者覆盖，跨楼层设备只标注了一处。1.1.0 改为坐标列表修复。

## 公用工程介质不计

水、循环水、冷冻水、蒸汽、导热油、冷媒、杂质等传热/公用介质不作为报警依据。
这些通常不在物性表中，因此不会命中甲乙类或有毒目录，天然被排除。
